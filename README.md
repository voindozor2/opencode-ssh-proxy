# OpenCode SSH Proxy

Локальный HTTP-прокси поверх SSH SOCKS для исходящих запросов OpenCode.
Использует уже установленные Python и OpenSSH; сторонних Python-пакетов нет.

```text
OpenCode → HTTP proxy 127.0.0.1:18080 → SSH SOCKS 127.0.0.1:18081 → VPS → HTTPS destination
```

## Текущий статус

- Реализованы HTTP CONNECT и обычные HTTP-запросы, локальная Basic-аутентификация,
  передача DNS-имён SOCKS-серверу и отказ без прямого обхода при недоступном SOCKS.
- Есть автоматические тесты с локальными HTTP/SOCKS/echo fixtures.
- По результатам ручной проверки владельца HTTP-мост вместе с реальным SSH
  прошёл HTTPS-запрос и повтор спустя три минуты, вернул 502 при остановке SSH
  и восстановился после повторного запуска SSH без перезапуска моста.
  Это не доказывает стабильность на длительном интервале.
- Реализован `supervisor.py`: управление собственным SSH-процессом, повторный запуск
  с backoff, один экземпляр на каталог настроек, закрытый вход до готовности SOCKS.
  `manage.ps1` предоставляет явные команды настройки, запуска и автозапуска.
- Механизм восстановления проверен с реальными локальными процессами-fixtures,
  а операции с ACL/ярлыком — во временном каталоге, не в настоящей автозагрузке.
- Владелец также проверил запуск/остановку supervisor с реальным SSH и автоматическое
  восстановление HTTPS после завершения только его дочернего SSH-процесса.
- **Реальный автоматический запуск при входе Windows, смена сети и интеграция
  OpenCode ещё не проверены.** Диагностический HTTPS не доказывает генерацию OAuth.

Подробные подтверждения и точка продолжения: [статус проверки](docs/verification-status.md).

## Файлы

- `bridge.py` — HTTP → SOCKS5, без управления процессом SSH.
- `test_bridge.py` — тесты без внешнего интернета и реальных секретов.
- `supervisor.py` — управляющий процесс для Windows, SSH и встроенного HTTP-моста.
- `manage.ps1` — явные Configure/Start/Stop/Status/InstallStartup/RemoveStartup.
- `test_supervisor.py`, `test_manage.py` — проверки управления процессами и Windows-скрипта.
- [Автозапуск Windows](docs/windows-startup.md) — установка, ограничения и откат.
- `AGENTS.md` — правила работы для агента, ограничения и план продолжения.

## Требования

- Windows с установленными OpenSSH Client и Python.
- Проверено на Python 3.14; другие версии и ОС пока отдельно не проверены.
- Собственный VPS с SSH-доступом; сервер должен разрешать TCP forwarding к нужным адресам.
- SSH-ключ, доступный без интерактивного ввода для будущего автоматического запуска.
- Проверенный ключ хоста в `known_hosts`. Не отключайте проверку ключа сервера.

Ни один скрипт в репозитории не устанавливает пакеты и не настраивает VPS,
firewall, VPN, системный прокси или OpenCode.

## Ручная проверка

Команды ниже выполняются в Windows PowerShell. Настройки и секреты хранятся
**вне клона репозитория**. Замените шаблоны на свои значения.

### 1. Подготовьте SSH

```powershell
$VpsHost = "YOUR_VPS_HOST"
$SshUser = "YOUR_SSH_USER"
$Key = "$HOME\.ssh\YOUR_PRIVATE_KEY"

ssh -T -o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 -i "$Key" "${SshUser}@${VpsHost}" "echo SSH_KEY_OK"
```

Ожидается `SSH_KEY_OK`, без запроса пароля. Если ключ хоста неизвестен или изменился,
сверьте fingerprint по независимому доверенному каналу, например консоли провайдера.
Не применяйте `StrictHostKeyChecking=no` и не доверяйте одному `ssh-keyscan`
как доказательству подлинности сервера.

### 2. Создайте пароль локального HTTP-прокси

Выполните **один раз**. Блок не перезаписывает существующий файл.

```powershell
$stateDir = Join-Path $HOME ".config\opencode-ssh-proxy"
New-Item -ItemType Directory -Path $stateDir -Force | Out-Null
$passwordFile = Join-Path $stateDir "proxy-password"
if (Test-Path -LiteralPath $passwordFile) {
    throw "Файл пароля уже существует. Не перезаписывайте его без согласования."
}

$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
try {
    $bytes = New-Object byte[] 32
    $rng.GetBytes($bytes)
} finally {
    $rng.Dispose()
}
[IO.File]::WriteAllText($passwordFile, [Convert]::ToBase64String($bytes), [Text.UTF8Encoding]::new($false))
$identity = [Security.Principal.WindowsIdentity]::GetCurrent().Name
icacls.exe "$passwordFile" /inheritance:r /grant:r "${identity}:(F)" '*S-1-5-18:(F)'
if ($LASTEXITCODE -ne 0) { throw "Не удалось ограничить ACL. Не запускайте мост до исправления прав." }
Remove-Variable bytes
```

Пароль не передаётся аргументом командной строки и не выводится. Basic-аутентификация
защищает локальный HTTP-вход, но не заменяет защиту учётной записи Windows и файла пароля.

### 3. Запустите SSH SOCKS

В том же окне, где заданы `$Key`, `$SshUser` и `$VpsHost`:

```powershell
ssh -N -T -D 127.0.0.1:18081 -i "$Key" -o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ConnectTimeout=10 -o ServerAliveInterval=15 -o ServerAliveCountMax=3 "${SshUser}@${VpsHost}"
```

Окно остаётся занятым процессом SSH. `ServerAlive*` помогает обнаружить обрыв,
но **не перезапускает SSH**. Ошибка занятого порта требует выяснить владельца,
а не завершать произвольный процесс. Если используете другой VPN, убедитесь,
что он не блокирует соединение с VPS. Автоматический обход такого VPN не настроен.

### 4. Запустите HTTP-мост

В другом PowerShell откройте каталог клона и выполните:

```powershell
python .\bridge.py --password-file "$HOME\.config\opencode-ssh-proxy\proxy-password"
```

Ожидается `Local HTTP bridge ready on 127.0.0.1:18080`.
Другие порты задаются через `--listen-port` и `--socks-port`.
Не запускайте мост поверх другого процесса на том же порту.

### 5. Проверьте HTTPS

В третьем PowerShell:

```powershell
$passwordFile = "$HOME\.config\opencode-ssh-proxy\proxy-password"
$proxyPassword = [IO.File]::ReadAllText($passwordFile).Trim()
curl.exe --silent --show-error --connect-timeout 10 --max-time 25 --proxy "http://127.0.0.1:18080" --proxy-user "opencode:$proxyPassword" --noproxy "localhost,127.0.0.1,::1" --write-out "\nCONNECT=%{http_connect} HTTP=%{http_code} TLS=%{time_appconnect}s total=%{time_total}s\n" "https://chatgpt.com/cdn-cgi/trace"
Remove-Variable proxyPassword
```

Ожидаются `CONNECT=200`, `HTTP=200` и внешний IP VPS в диагностическом ответе.
Повторите спустя несколько минут, не переключая сеть. URL приведён для ручной
диагностики, скрипт не обращается к нему автоматически. Не используйте `curl -v`
с реальными токенами. Пароль в `--proxy-user` может быть доступен через список
аргументов процесса curl локальному пользователю с соответствующими правами.

Проверьте отказ: остановите SSH через Ctrl+C, оставив мост работающим, и повторите
запрос. Ожидается ошибка прокси, не прямое соединение. После остановки моста
запрос через него должен завершаться ошибкой подключения.

## Подключение OpenCode — следующий, ещё не проверенный этап

Официальная документация V2: <https://opencode.ai/v2/docs/network>.
Подтверждён HTTP-прокси; поддержка SOCKS URL в managed service не установлена.
Поэтому мост предоставляет обычный HTTP-вход для CONNECT.

План оставшейся настройки:

1. Проверить управляющий процесс с реальным SSH, отказ и восстановление после потери сети.
2. По явному разрешению установить автозапуск и проверить повторный вход Windows.
3. Сохранить `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` через штатный CLI OpenCode,
   не редактируя приватный `service.json` вручную. Экранировать пароль в proxy URL.
4. **Заранее предупредить о разрыве текущей сессии:** изменение managed env
   останавливает сервис. Не переключать его посреди несохранённой работы.
5. Проверить локальный API, реальный запрос выбранной модели, обрыв и восстановление.

Обычные приложения не должны получать системные proxy env/settings.
Прокси процесса OpenCode может затронуть не только модель, но и другие его исходящие
HTTP-запросы. Учитывайте `NO_PROXY=localhost,127.0.0.1,::1`.

## Безопасность и ограничения

- Оба локальных слушателя привязываются только к `127.0.0.1`.
- Мост не управляет ключами, не перехватывает TLS и не хранит OAuth-токены.
- HTTP-запросы и CONNECT проходят только через SOCKS. Прямого fallback нет.
- Для имён используется SOCKS5 domain addressing, без локального DNS-разрешения цели.
- Авторизация HTTP-прокси не передаётся целевому серверу.
- SSH защищает путь до VPS; обычный HTTP **после VPS не зашифрован**.
  Для токенов и содержимого модели нужен HTTPS с проверкой сертификата.
- VPS видит адреса назначений и метаданные; сквозной HTTPS не передаёт ему
  открытый текст токенов. Это не обещание полной анонимности.
- Нет access log, загрузки обновлений, телеметрии и неявной установки автозапуска.
  Управляющий процесс пишет только фиксированные события и код завершения SSH,
  без целевых URL, SSH stderr, ключей, паролей или HTTP-заголовков.
- Это небольшой локальный инструмент, не публичный production proxy. Нет квот
  потоков, развитого контроля нагрузки или независимого security-аудита.
- Relay закрывает неактивный туннель после 180 секунд; медленный получатель
  может вызвать тайм-аут записи через 15 секунд. Длинные стримы отдельно не проверены.
- Работоспособность OpenSSH/Python и их обновление остаются ответственностью окружения.

## Тесты

```powershell
python -m unittest discover -v
```

Тесты используют только loopback и тестовый пароль. Они проверяют авторизацию,
CONNECT с непрозрачными байтами, обычный HTTP/POST, передачу имени SOCKS-серверу,
отсутствие утечки proxy authorization, некорректные URL и отказ без прямого обхода.
Тесты управляющего процесса дополнительно проверяют перезапуск локального дочернего
SOCKS, контроль владельца порта, Job Object и остановку. PowerShell-тесты создают
приватный state/ярлыки только во временных fixtures. Они **не** проверяют реальную
сеть, TLS-сертификаты, VPS, вход Windows, OpenCode или провайдера.

## Остановка и удаление

Для ручного сценария остановите мост и SSH через Ctrl+C в соответствующих окнах.
Для управляющего процесса используйте `manage.ps1 -Action Stop`; для удаления
автозапуска отдельно `manage.ps1 -Action RemoveStartup`, как описано в
[инструкции Windows](docs/windows-startup.md). Проект не создаёт службы или задания
планировщика и не требует серверного отката.
Клон и локальные файлы можно удалить отдельно после проверки их состава.
Если в будущем будут сохранены proxy env OpenCode, сначала восстановите согласованные
прежние значения через CLI; простое удаление моста иначе оставит OpenCode без сети.
