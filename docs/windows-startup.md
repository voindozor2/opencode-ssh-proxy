# Управляемый запуск на Windows

## Что реализовано и чего пока нет

`supervisor.py` запускает HTTP-мост в своём процессе и один дочерний OpenSSH.
SSH слушает SOCKS только на loopback. При завершении SSH supervisor повторяет
запуск с задержками 1, 2, 4, 8, 16, 30 секунд; далее максимум 30 секунд.
После соединения, продержавшегося 60 секунд до выхода SSH, backoff сбрасывается.
`ServerAliveInterval=15` и `ServerAliveCountMax=3` помогают SSH обнаружить потерю
транспорта; это не обещание обнаружить любой зависший канал за точные 45 секунд.

HTTP-запрос без правильной авторизации получает 407. Пока supervisor не обнаружил
SOCKS LISTEN именно своего SSH PID через Windows API, авторизованный запрос
получает 503. Отказ уже выбранного SOCKS может вернуть 502. Direct fallback нет.
Готовность локального порта **не является** проверкой доступа к реальной модели.

Windows Job Object с kill-on-close завершает назначенный SSH при выходе supervisor,
включая принудительное завершение. Нормальная остановка дополнительно дожидается
ребёнка. Назначение в Job выполняется сразу после создания процесса; краткое окно
между созданием и назначением не устранено. Чужие процессы не завершаются.
При занятом HTTP-порте запуск прекращается; при занятом SOCKS-порте запросы
остаются закрытыми, а supervisor ждёт освобождения с backoff, не используя чужой
listener. Занятый SOCKS-порт уже при начальном запуске также приводит к отказу запуска.

Один экземпляр на каталог настроек обеспечивается блокировкой файла Windows,
не доверенным PID-файлом. Стоп-команда создаёт запрос в том же приватном каталоге;
supervisor закрывает свой мост и ребёнка. Не удаляйте lock-файл для «лечения»:
после завершения процесса блокировка освобождается ОС, сам файл может оставаться.

## Постоянное место исходников

**Не устанавливайте автозапуск из Temp.** Склонируйте репозиторий в постоянный
пользовательский каталог. Используйте URL этого репозитория, например:

```powershell
$repo = Join-Path $HOME 'Projects\opencode-ssh-proxy'
New-Item -ItemType Directory -Path (Split-Path $repo) -Force | Out-Null
git clone 'YOUR_REPOSITORY_URL' "$repo"
Set-Location $repo
```

Если каталог уже существует, сначала проверьте его remote, ветку и изменения;
не перезаписывайте и не делайте reset. Изменение пути клона/Python впоследствии
требует снять старый ярлык из старого клона и установить новый.

## Настройка: отдельное явное действие

Команды — обычный Windows PowerShell, не администратор. Скрипт использует Python
из PATH; при необходимости передайте полный путь через `-PythonExecutable`.
`pythonw.exe` для скрытого запуска должен находиться рядом с этим Python.

```powershell
.\manage.ps1 -Action Configure -VpsHost 'YOUR_VPS_HOST' -SshUser 'YOUR_SSH_USER' -IdentityFile "$HOME\.ssh\YOUR_PRIVATE_KEY"
```

По умолчанию создаётся `$HOME\.config\opencode-ssh-proxy` с:

- `settings.local.json` — адрес сервера, пользователь, пути к SSH/ключу/паролю, порты;
- `proxy-password` — случайный пароль, если не передан существующий файл;
- `instance.lock`, `stop.request` — служебные файлы;
- `supervisor.log` и до трёх архивов по 256 КиБ — только события, без содержимого SSH.

ACL нового выделенного state-каталога ограничиваются текущим пользователем и SYSTEM.
Уже существующий непустой каталог и существующая конфигурация **не перезаписываются**.
Если ранее выполнялся ручной сценарий README в этом же каталоге, используйте новый
`-StateDirectory` и затем указывайте его во всех командах управления.

Можно переиспользовать существующий пароль через `-PasswordFile 'ABSOLUTE_PATH'`.
Его содержимое и ACL не меняются: отдельно убедитесь, что посторонние не имеют
доступа. SSH-ключ также не изменяется. Все локальные файлы остаются вне Git.
Настройка не создаёт автозапуск, не запускает туннель, не меняет VPS или OpenCode.

Если PowerShell запрещает выполнение скриптов, не меняйте глобальную execution policy
автоматически. После просмотра кода можно явно разрешить запуск только этого процесса:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\manage.ps1 -Action Status
```

## Запуск, состояние, остановка

Перед запуском остановите свои ручные SSH/bridge через Ctrl+C. Если порт занят
неизвестным процессом, выясните владельца; не используйте массовый Stop-Process.

```powershell
.\manage.ps1 -Action Start
.\manage.ps1 -Action Status
```

Повторный Start не создаёт второй экземпляр с тем же state. `RUNNING` означает
только работающий supervisor, **не** успешную авторизацию SSH или доступность модели.
Для диагностики запускайте в консоли:

```powershell
python .\supervisor.py --config "$HOME\.config\opencode-ssh-proxy\settings.local.json"
```

SSH stdout/stderr не сохраняются: адреса, usernames и сообщения стороннего сервера
не попадают в журналы. При повторном `ssh_exited code=255` отдельно выполните ручную
безопасную проверку ключа из README. Пользовательский SSH config игнорируется через
`-F NUL`; известные ключи сервера по умолчанию всё равно берутся из `known_hosts`.
ProxyCommand/ProxyJump и интерактивная авторизация не применяются.
Текущая конфигурация использует SSH-порт 22; нестандартный порт пока не предусмотрен.

```powershell
.\manage.ps1 -Action Stop
```

Stop идемпотентен. Если запрос не обработан за 15 секунд, команда сообщает ошибку,
не пытаясь убить PID из файла или все ssh/python в системе.

## Проверка перед автозапуском

Подтверждённые результаты конкретной настройки и следующий шаг записаны в
[контрольной точке](verification-status.md). Не запускайте весь сценарий повторно
без изменения окружения или нового сбоя. Следующий список описывает виды проверок,
а не утверждает, что они все ещё не выполнены.

1. Через HTTP-прокси выполните HTTPS-диагностику из README, проверьте IP VPS и повтор
   через несколько минут, не переключая сеть.
2. По владельцу HTTP-порта и Windows process tree найдите именно этот supervisor,
   сверив путь к `pythonw.exe`, путь к `supervisor.py` и путь к конфигу в его аргументах.
   Затем найдите единственный дочерний SSH с ожидаемым ExecutablePath, повторно
   проверьте принадлежность перед завершением и остановите только его.
   Supervisor должен остаться тем же, новый SSH — получить другой PID, а HTTPS —
   восстановиться без ручного Start и перезапуска моста. Не завершайте все SSH по имени,
   не используйте PID из старого отчёта; в безопасном журнале PID не записывается.
3. Отдельно проверьте потерю/возврат сети и перезапуск Windows. Автозапуск не обходит
   другой VPN: если тот блокирует VPS, SSH будет повторять попытки до восстановления пути.
4. Убедитесь, что при отказе SSH нет прямого обхода. Ответ 502 или 503 ожидаем.

## Установка автозапуска — только после согласия

```powershell
.\manage.ps1 -Action InstallStartup
```

Создаётся ровно один `OpenCodeSSHProxy.lnk` в пользовательской папке Startup.
Он вызывает `pythonw.exe` с путями к supervisor и внешнему config. В ярлыке нет пароля
или содержимого ключа. Повторная установка совпадающего ярлыка ничего не дублирует;
чужой или отличающийся ярлык с тем же именем не перезаписывается.
Команда не запускает процесс немедленно; для этого есть Start.
Службы, задачи планировщика, HKLM, системный proxy и OpenCode не меняются.

## Откат

```powershell
.\manage.ps1 -Action RemoveStartup
.\manage.ps1 -Action Stop
```

Удаляется только совпадающий ярлык; повторное удаление безопасно. Конфиг, журналы,
пароль и SSH-ключ остаются для проверки и возможного восстановления. Не удаляйте
приватные файлы и клон рекурсивно без проверки состава и разрешения владельца.
Если позже были настроены proxy env OpenCode, сначала восстановите согласованную
прежнюю конфигурацию через его CLI, иначе остановленный мост оставит его без сети.

## Проверки реализации

```powershell
python -m unittest discover -v
```

Выполняются локальные fixtures: настоящий дочерний SOCKS-процесс вместо SSH,
его остановка/повторный запуск, передача непрозрачных байтов через CONNECT,
Job Object, проверка TCP PID, блокировки и очистка портов. PowerShell-тесты
проверяют реальную Windows ACL и ярлыки в **тестовой** папке Startup, включая
идемпотентность и отказ изменять чужой ярлык. Не используются настоящий VPS,
автозагрузка пользователя или OAuth. Наличие этих тестов не закрывает ручные
проверки реального SSH, входа Windows и OpenCode.
