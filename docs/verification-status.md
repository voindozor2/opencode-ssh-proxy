# Контрольная точка настройки

Эта запись сохраняет результат работы для следующей сессии агента. Это история
подтверждений, **не** запрос к текущему состоянию Windows. Перед действиями проверяйте
актуальные процессы, локальные настройки, версию клона и согласие пользователя.
Реальные адреса, usernames, ключи, пароли, PID и сетевые дампы здесь не хранятся.

## Цель и выбранный путь

Автоматически направлять HTTP(S)-запросы сервиса OpenCode через собственный VPS,
не включая вручную системный VPN и не меняя маршруты обычных приложений.
Рабочая цепочка: OpenCode → локальный HTTP-мост → SSH SOCKS → VPS → HTTPS.
Исходники должны оставаться в репозитории; перед установкой нового ПО владелец
требует ссылку на исходники и проверку кода. Текущая реализация использует уже
установленные Python/OpenSSH, без сторонних Python-пакетов.

WireGuard испытывал воспроизводимый обрыв после начала TLS, в том числе на другом
UDP-порте. Похожий симптом был на домашней и мобильной сети. Парные захваты показали
потерю между сетевыми точками Windows и VPS, но не установили конкретную причину.
Не объявлять доказанными DPI, вину VPN-клиента или провайдера. Не возвращаться к
изменениям DNS/MTU/firewall без новых данных или запроса пользователя.

| Проверка | Источник | Результат и границы |
| --- | --- | --- |

| HTTP-мост + настоящий SSH | Вывод владельца | Два CONNECT 200 / HTTP 200, включая повтор через три минуты. |
| Отказ без direct fallback | Вывод владельца | После остановки SSH работающий мост вернул CONNECT 502, не ответ с прямого IP. |
| Восстановление отдельного моста | Вывод владельца | После ручного запуска SSH вернулись CONNECT 200 / HTTP 200 без перезапуска моста. |
| Configure управляющего процесса | Вывод владельца | В постоянном клоне созданы внешние настройки с существующими ключом/файлом пароля; проверка конфигурации успешна. Конфиг не в Git. |

| Установка автозапуска пользователя | Вывод владельца | InstallStartup сообщил: Startup entry installed for the current user. No process started. Ярлык установлен; запуск после входа Windows этим не подтверждён. |

Нет настоящего VPS/OAuth в автотестах. |

## Точка продолжения

1. **Установка настоящего ярлыка автозапуска подтверждена выводом владельца.**
   Повторять InstallStartup без изменения пути/настроек не требуется. Откат —
   RemoveStartup по операционной инструкции; он не останавливает работающий процесс.
2. Отдельно проверить настоящий выход/вход Windows
   либо перезагрузку: один supervisor, свой SSH, успешный HTTPS без ручного Start.
   Не инициировать выход/перезагрузку автоматически и не обрывать работу владельца.
3. Проверить потерю/возврат сети, длительную работу и взаимодействие с другим VPN.
   Ранее при активном другом VPN SSH к VPS был недоступен. Это ограничение текущего
   пути, а не реализованное автоматическое исключение. Не обещать обход этого VPN.
4. **OpenCode ещё не переключён.** Подготовить план и откат managed proxy env по
   актуальной документации V2: <https://opencode.ai/v2/docs/network>.
   Перед изменением предупредить: service set env останавливает сервис и может
   прервать текущую сессию. Не выводить приватный service config или proxy URL
   с паролем. Не менять глобальные env/системный proxy вместо env сервиса.
5. Проверить локальный API и реальный запрос выбранной модели через уже существующую
   OAuth-авторизацию. Trace 200 и неавторизованный API 401 не являются такой проверкой.
   Проверить поведение OpenCode при обрыве и после восстановления; не объявлять
   fail-closed для всего OpenCode доказанным только тестом Python-моста.

Операционные команды, требования к постоянному клону, приватные ACL, диагностика,
установка ярлыка и откат: [windows-startup.md](windows-startup.md).
Первичная ручная проверка HTTP-моста: [README](../README.md).

## Локальные настройки и безопасная передача

- Постоянный клон размещён пользователем вне Temp. Путь выяснять локально, не
  запускать устаревшую временную копию только потому, что она осталась в истории.
- По умолчанию настройки находятся в `$HOME/.config/opencode-ssh-proxy/settings.local.json`.
  Фактический путь подтверждается аргументами supervisor или пользовательским выбором.
- Файл пароля может находиться в прежнем внешнем каталоге: использовать `password_file`
  из локальных настроек, не создавать новый пароль и не менять путь без причины.
- В этом окружении протокол проходит через SSH-порт 22; реальные host/user/key paths
  берутся из внешней конфигурации. Не публиковать её даже в приватном репозитории.
- При новой проверке записывать вывод без секретов и границы результата. Не повышать
  «команда предложена» до «установлено», «процесс RUNNING» до «модель работает» или
  «SSH перезапущен» до «восстановление после смены сети проверено».
- После исполнения оставшихся этапов точечно обновить эту запись, README и AGENTS,
  не оставляя противоречивые утверждения о готовности.
