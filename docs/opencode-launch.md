# Обычная команда OpenCode с прокси

## Использование

После установки обёртки и открытия **нового** терминала используйте обычные команды:

```powershell
opencode
opencode "E:\Projects\YOUR_PROJECT"
opencode run "Ответь только OK"
opencode mini
```

Без аргументов открывается обычный терминальный интерфейс в текущем каталоге.
Каталог проекта не закреплён в обёртке; аргументы, Unicode, кавычки и код завершения
передаются нативному CLI. Поддерживаемый OpenCode выбор проектов остаётся доступен.
Для TUI, `run` и `mini` автоматически добавляется `--standalone`, если пользователь
сам не указал сервер или этот флаг. Это исключает случайное подключение к старому
общему серверу без proxy env. Модель, транспорт, плагины и OAuth не меняются.

Ярлык **OpenCode via SSH** открывает тот же терминальный интерфейс без аргумента
проекта. Начальный рабочий каталог — домашний каталог пользователя. Это не Desktop GUI.
Можно выбрать другой проект внутри интерфейса или запускать команду из его каталога.

## Как это устроено

`manage-command.ps1` компилирует `command-shim.cs` штатным .NET Windows PowerShell
в `$HOME/.local/opencode-proxy/bin/opencode.exe`. Скачивания и новые пакеты не нужны.
В начало **пользовательского PATH** добавляется только этот выделенный каталог.
Существующие файлы установленного OpenCode, профили shell и системный PATH не меняются.
Машинный PATH обычно предшествует пользовательскому; после установки проверьте
фактическое разрешение команды. Alias/function в shell тоже может иметь приоритет.

Небольшой exe запускает существующий Python и `command_launcher.py`, корректно
экранируя Windows argv без `cmd /c`. Пароль не передаётся аргументами процессов.
Python читает внешний `settings.local.json` и `password_file`, кодирует пароль
в proxy URL и задаёт `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY=localhost,127.0.0.1,::1`
**только дочернему процессу OpenCode**. Окружение вызывающего терминала не меняется.

Мост и SSH должны работать: supervisor уже поддерживает отдельный автозапуск
по [windows-startup.md](windows-startup.md). Команда не запускает второй supervisor.
Недоступный мост/SSH приводит к сетевой ошибке, а не к переключению обёртки на direct.
Команды вроде `--version` могут работать без доступного прокси. Наличие слушателя
не доказывает готовность SSH или модели; нужен настоящий ответ модели.

### Границы действия

- Охвачена команда `opencode` из PATH и новый ярлык. Прямой запуск оригинального
  `opencode-cli.exe`, Desktop GUI и старые абсолютные пути обходят обёртку.
- Явный `--server` сохраняется: маршрут модели тогда задаёт выбранный сервер,
  а не окружение локального клиента. Не выдавайте такой запуск за проверку прокси.
- Служебные подкоманды (`service`, `api` и другие) передаются без искусственного
  `--standalone`. Они могут обращаться к существующему общему серверу.
- Дочерние инструменты OpenCode тоже могут наследовать proxy env. Программы,
  игнорирующие эти переменные, могут выходить напрямую. Это не фильтр трафика ОС
  и не доказанный fail-closed для всех сетевых функций OpenCode.
- Сессии/авторизация остаются в пользовательском хранилище. Не выполняйте одновременно
  запись в одну сессию из разных private servers.
- Нативный CLI и Python фиксируются при установке в приватном `command.local.json`
  и скомпилированной обёртке. После перемещения клона/Python или обновления OpenCode
  с удалением старого exe нужна явная переустановка. Автообновления обёртки нет.

## Установка и откат (Windows PowerShell)

Исходники: `command-shim.cs`, `command_launcher.py`, `manage-command.ps1`.
Существующие Python/OpenSSH и внешний конфиг должны быть уже настроены.
Ниже размещение принятого постоянного клона; при другом размещении измените путь.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\Projects\opencode-ssh-proxy\manage-command.ps1" -Action Install -PythonExecutable "$env:LOCALAPPDATA\Programs\Python\Python314\python.exe"
```

Скрипт сохраняет исходный пользовательский PATH с его registry type и manifest
в приватном `command-install-before.json` **до изменения PATH**, с закрытым ACL.
Другие переменные Windows не меняются. Повтор с теми же параметрами допустим;
чужой/изменённый exe или runtime config не перезаписывается.
`-PathFixture` предназначен только для тестов: он заменяет registry/PATH файл-fixture,
не настоящий PATH, и не используется для обычной установки.

Создать отдельный ярлык без замены старых ярлыков и без изменения автозагрузки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\Projects\opencode-ssh-proxy\install-launcher-shortcut.ps1" -ShortcutDirectory ([Environment]::GetFolderPath('Desktop'))
```

Ярлык не содержит пароля или аргумента проекта. `-ProjectDirectory` меняет только
его стартовый рабочий каталог; по умолчанию HOME. Чужой существующий ярлык не заменяется.

Уже открытые терминалы/IDE наследовали прежний PATH. Закройте и заново откройте
приложение терминала из меню «Пуск»; для Windows Terminal иногда нужно закрыть все
его окна. Текущие процессы установки не перезапускает. Проверка в новом PowerShell:

```powershell
(Get-Command opencode -CommandType Application | Select-Object -First 1).Source
opencode --version
```

Первый путь должен оканчиваться на `.local\opencode-proxy\bin\opencode.exe`.
Затем без системного VPN проверьте настоящий ответ модели и новый ярлык.

Откат команды (закройте клиенты, запущенные через неё):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$HOME\Projects\opencode-ssh-proxy\manage-command.ps1" -Action Remove
```

Удаляется только собственная запись PATH и проверенные по manifest файлы обёртки.
Другие изменения PATH после установки сохраняются; полный старый PATH вслепую
не восстанавливается. Backup архивируется во внешнем state-каталоге и остаётся
доступным. Новая установка после удаления разрешена. Для удаления ярлыка удалите
только **OpenCode via SSH** через Проводник. Прокси/supervisor и общий сервис
не останавливаются и не перенастраиваются этим откатом.

## История диагностики и старые managed env

Сводная инструкция отката только команды или всей интеграции, включая старые
managed env и автозапуск SSH: [rollback.md](rollback.md). Сам откат при публикации
не выполнялся.

Владелец подтвердил настоящий ответ модели без VPN после запуска **клиента**
с proxy env. Отдельный диагностический `run --standalone` также получил `OK`.
В прежних неудачных попытках managed env сохранялись CLI, но у работавших клиента
и сервера отсутствовали. HTML 403 содержал IP, отличный от VPS. Точная внутренняя
причина запуска сервера без env не установлена. WebSocket причиной не объявлять:
смена транспорта, аккаунта и плагинов не понадобилась.

Локальные `switch-opencode-proxy.ps1`, `restore-opencode-proxy.ps1` и timestamped
backups находятся вне Git в `$HOME/.config/opencode-ssh-proxy`. Они не являются
зависимостью новой команды. Managed env ранее сохранялись и могут оставаться
настроенными; их наличие не считать исходным состоянием. Не печатать их значения.
Для отката старых экспериментов согласовать конкретный исходный backup, а не
просто самый новый. Изменение managed env может остановить сервис и оборвать сессию;
обёртку не устанавливать путём ручного редактирования `service.json`.

`launch-opencode.ps1` остаётся вспомогательным ручным запускателем без передачи
произвольных аргументов. Для повседневной работы используйте установленный `opencode`.

## Что ещё проверить

Автотесты компилируют настоящий shim и проверяют цепочку exe → Python → fake CLI,
аргументы/окружение/cwd/exit code, установку/удаление PATH через fixture-файл и ярлыки
во временном каталоге. Это не реальная проверка VPS, входа Windows или модели.
Актуальные реальные результаты: [verification-status.md](verification-status.md).
Работа после сообщённой владельцем перезагрузки подтверждена без ручного Start
и системного VPN. Источник факта перезагрузки — владелец; cold boot ядра и конкретный
способ открытия клиента отдельно не установлены. Остаются потеря/возврат сети
и длительная работа.

Официальный контракт private server: <https://opencode.ai/v2/docs/cli>.
